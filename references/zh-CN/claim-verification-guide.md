# 主张验证指南

本文档提供一套验证事实主张的方法，帮助学习者识别 AI 生成内容中的错误、过时信息和伪造引用风险。

## 什么需要验证

不是每句话都需要验证。优先验证以下内容：

- 具体数字、日期、版本号、价格、排名、benchmark
- 论文、作者、机构、书名、法规、官方文档
- 医疗、法律、金融、安全、认证相关主张
- 与当前版本或最新政策有关的内容
- 没有来源但会影响学习判断的关键结论

## 验证步骤

### 1. 把主张写清楚

把要验证的内容改写成一句可判断真假的话。

示例：

- “React Hooks 在 React 16.8 中正式发布。”
- “某模型在某 benchmark 上取得某分数。”
- “某法规在某日期开始生效。”

### 2. 优先查一级来源

根据领域选择权威来源：

| 领域 | 优先来源 |
| --- | --- |
| 编程语言 | 官方文档、语言规范、release notes |
| 软件框架 | 官方文档、GitHub release、changelog |
| 计算机科学理论 | 教材、原始论文、课程资料 |
| 医疗科学 | WHO、CDC、FDA、专业协会 guideline、PubMed |
| 法律法规 | 政府法规数据库、法院或监管机构文件 |
| 金融税务 | 监管机构、税务机关、正式会计准则 |

### 3. 交叉验证

对关键主张至少找两个独立来源。独立来源指它们不是互相转述，也不是都来自同一篇文章。

当来源冲突时，优先级如下：

1. 一级来源优于二级来源。
2. 新来源优于旧来源，特别是技术、法规和价格类信息。
3. 具体版本或地域来源优于泛泛解释。
4. 同行评审或官方文件优于论坛和社交媒体。
5. 无法判断时，在 `claim_ledger.md` 中标记为 `[有争议]`。

### 4. 记录验证结果

在 `09_sources/claim_ledger.md` 中记录：

```markdown
| 主张 | 模块 | 状态 | 查阅来源 | 结论 | 日期 |
| --- | --- | --- | --- | --- | --- |
| React Hooks 在 React 16.8 发布 | 01_core_concepts/02-hooks.md | 已验证 | React 官方博客、release notes | 正确 | 2026-01-15 |
```

状态建议：

- `已验证`
- `未验证`
- `有争议`
- `部分正确`
- `已过时`
- `错误`

### 5. 更新待验证清单

完成验证后，同步更新 `09_sources/claims_to_verify.md`：

```markdown
- [x] React Hooks 在 React 16.8 发布 — 结果：已通过 React 官方资料确认
- [ ] 某 benchmark 分数 — 需要查原始评测报告
```

## 无联网时的处理

如果 Agent 没有联网能力：

1. 生成内容必须标记为 `未验证草稿`。
2. 不得编造链接、发布日期、DOI、论文或 benchmark。
3. 对关键事实使用 `[未验证]`。
4. 在 `claims_to_verify.md` 中列出具体待验证主张。
5. 给出建议验证路径，例如“查阅官方文档的 release notes”。

## 快速检查表

- [ ] 这是不是事实主张，而不是观点？
- [ ] 是否有一级来源？
- [ ] 是否有两个独立来源支持？
- [ ] 是否检查了发布日期或版本？
- [ ] 是否存在地域、版本或适用范围限制？
- [ ] 是否记录到 `claim_ledger.md`？
- [ ] 是否更新 `claims_to_verify.md`？
