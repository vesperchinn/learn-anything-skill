# Learning Methodology

The pedagogical foundation of the Learn Anything Skill Pack — based on the article "How to Use Codex to Quickly Learn Any Domain" by @GeekCatX.

## The Five Systems

A complete learning system has five interconnected subsystems. Most learners only have one or two. The Skill Pack builds all five:

### 1. Knowledge Map System

**Problem solved**: "I don't know what this field contains."

Before learning anything specific, you need to see the whole landscape. The knowledge map shows:
- What problems the field solves
- The 20 most important concepts and how they relate to one another
- What is essential (20%), what to skip (60%), and what to save for later (20%)
- Common confusion points to watch for
- A staged learning path with a concrete deliverable at each stage

### 2. Glossary System

**Problem solved**: "I don't understand the terminology."

Every field has its own jargon. A running glossary that grows with your learning:
- Each term defined in plain language
- Connected to the concepts that use it
- Updated every time you encounter a new term

### 3. Exercise System

**Problem solved**: "I thought I understood, but I didn't."

The gap between "sounds right" and "can do it" is where real learning happens:
- Daily targeted exercises (5 questions minimum)
- Every wrong answer gets an error-type diagnosis before correction
- Weak points are tracked and revisited systematically

### 4. Project System

**Problem solved**: "I learned a lot but can't apply it."

Knowledge without application is fragile. A capstone project forces integration:
- Designed around the learner's specific weak points
- Small enough to complete in 7 days
- Must be runnable, demonstrable, and explainable

### 5. Review System

**Problem solved**: "I forget everything and never fix my mistakes."

Without systematic review, learning decays exponentially:
- Daily review: what was learned, what was missed, what comes next
- Weekly stage tests: examiner-mode assessment with scoring and diagnosis
- Knowledge compression cards: one card per day or module for spaced repetition
- `progress.md` snapshot: an always-current dashboard of strengths and gaps

## The 20-60-20 Rule

For any domain, categorize knowledge into three tiers:

| Tier | Proportion | Strategy |
|------|-----------|----------|
| **Must-learn-now** | 20% | Master immediately. Gatekeeping knowledge — without this, nothing else makes sense. |
| **Skip-for-now** | 60% | Consciously ignore. This is the "shiny object" tier — exploring it feels productive but diffuses focus. |
| **Learn-later** | 20% | Save for after the project. Advanced topics that only make sense with hands-on experience. |

Most learners fail because they spend 80% of their time on the middle 60%.

## The Daily Cycle

Every day must hit four modes:

```
Learn -> Practice -> Output -> Test
  |                            |
Input new concepts      Verify understanding
(3 or fewer per day)    (5+ questions)
        |                       |
    Apply immediately    Diagnose errors
    (targeted exercises) (4 error types)
              |
         Create something
         (60-minute task max)
```

**Learning without output is consumption, not education.**

## Error Diagnosis

When a learner makes a mistake, never just give the correct answer. Diagnose the error type first:

| Type | Signal | Fix |
|------|--------|-----|
| **Concept Gap** | "I've never heard of this" | Return to definition + analogy |
| **Application Failure** | "I know what it is but can't do it" | Hands-on exercise + imitation |
| **Expression Unclear** | "I get it but can't explain it" | Feynman technique + verbal practice |
| **Knowledge Confusion** | "Isn't that the same as X?" | Side-by-side comparison table |

## Why Files, Not Chat

The core insight: AI chat is ephemeral. Files are permanent.

- Chat history gets lost. A Git repository persists.
- Chat does not track state. `progress.md` is a state machine.
- Chat does not show growth. A repository of 30 days of reviews, flashcards, and projects is a portfolio.
- Chat is one agent's memory. Files are transferable across agents and tools.
