# 案例分析：Auto-GPT — 第一个爆火的自主 Agent

## 概述
**Auto-GPT**（2023年3月）是第一个在 GitHub 上获得超过 16 万 Stars 的开源自主 Agent 项目。它展示了 Agent 范式的全部潜力——同时也暴露了早期 Agent 的核心问题。

## 它做了什么
给定一个高层目标（如"研究排名前三的电动汽车公司并写一份对比报告"），Auto-GPT 能够：
1. 自动拆解目标为子任务
2. 搜索互联网获取信息
3. 读写本地文件保存中间结果
4. 对自己的输出进行自我批评和改进
5. 在遇到障碍时尝试替代方案

## 架构
```
用户目标 → Agent 循环:
  1. 思考: "下一步做什么？"
  2. 行动: 执行命令（搜索、写文件、浏览网页）
  3. 观察: 读取结果
  4. 评判: "结果够好了吗？"
  5. 重复或结束
```

## 成功的方面
- 展示了 Agent 可以自主运行数十分钟完成复杂任务
- 证明了 Think→Act→Observe 循环的有效性
- 激发了整个 Agent 生态的爆发（BabyAGI、CrewAI、LangGraph……）

## 失败的方面
- **死循环**: Agent 经常陷入"搜索→不满意→搜索→不满意"的死循环
- **Token 消耗巨大**: 一个简单任务可能消耗数万 tokens
- **效果不稳定**: GPT-3.5 时代的推理能力不足以支撑可靠的自主决策
- **缺乏安全护栏**: Agent 可能执行危险操作（删除文件、发送垃圾请求）

## 给学习者的关键教训
1. **ReAct 循环是核心，但不加限制会失控**: 需要最大步数限制、成本上限
2. **LLM 的能力决定 Agent 的上限**: GPT-4 的 Auto-GPT 比 GPT-3.5 的可靠 10 倍
3. **Human-in-the-loop 不是可选项，是必需品**: 关键决策需要人类确认
4. **Tool 的定义比 Tool 的数量更重要**: 好的工具描述比堆 20 个工具更有效
