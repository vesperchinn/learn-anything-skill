# 第 3 天 — 2026-06-13

## 一句话总结
Tool Use / Function Calling 让 Agent 从「只会说话」变成「能做事」——需要精确能力时调用专门的工具而非凭记忆猜测。

## 5 个关键词
1. **工具使用** — Agent 调用外部工具（搜索、计算、API）的能力
2. **Function Calling** — 工具使用的技术实现：LLM 生成 JSON 格式的工具调用请求
3. **Schema** — 工具定义格式：名称、描述、参数类型、是否必填
4. **编排** — 多工具的协调调用：何时用搜索、何时用计算、何时用代码执行
5. **降级策略** — 工具调用失败时的备用方案：重试、换工具、或向用户求助

## 3 个应用场景
1. 信息检索 Agent：检测到需要实时数据 → 调用 search_web("今天天气") → 无结果时换 search_weather_api()
2. 数据分析 Agent：用户问「上季度销售额趋势」→ 调用 query_db(SQL) → 调用 plot_chart(data) → 返回图表
3. 代码助手 Agent：用户要求「重构这个函数」→ 调用 read_file() → 调用 run_tests() → 确认通过后提交

## 2 个常见误区
1. ❌ 给 Agent 太多工具（20+），导致每次选择工具都出错 → ✅ 从 1-2 个工具开始，验证正确率后再增加
2. ❌ 工具描述写得太模糊（"searches for things"）→ ✅ Schema 必须精确：名称、用途、每个参数的类型和含义

## 1 个经典案例
**ChatGPT 联网搜索** — 2023 年推出的插件系统让 ChatGPT 从纯语言模型变成能搜索网页、执行代码、生成图像的 Agent。这证明了 Tool Use 是区分「语言模型」和「Agent」的关键能力。

## 最可能忘记的内容
Tool schema 中的 `description` 字段是最重要的——LLM 靠它来判断何时调用哪个工具。写 schema 的本质是「写给 LLM 看的 API 文档」。
