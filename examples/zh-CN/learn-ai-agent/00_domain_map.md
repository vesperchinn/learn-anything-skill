## 1. What Problem Does This Field Solve?

AI Agent 解决的核心问题是：**如何让 AI 不仅回答问题，还能自主完成复杂的多步骤任务**。没有 Agent 技术，大语言模型只能做「一问一答」；有了 Agent，AI 可以自己制定计划、调用工具、记忆上下文、在失败后自我纠错——像一个真正的数字助手一样独立完成工作。

## 2. Feynman Explanation

想象你有一个非常聪明但从未离开过房间的实习生。你可以问他任何问题，他都能在书本中找到答案——但他不能帮你订机票、不能帮你整理邮件、不能帮你做调研。现在，你给这个实习生配了电脑、网络、电话，还教他「遇到不懂的先查资料、做错了就换方法、做完后检查一遍」。这个升级版的实习生，就是一个 AI Agent。

## 3. Top 20 Core Concepts

| # | Concept | One-Line | Difficulty |
|---|---------|----------|------------|
| 1 | **Agent** | 能感知环境、制定计划、执行动作并自我纠错的自主系统 | Beginner |
| 2 | **LLM** | Agent 的「大脑」，负责理解语言、推理和决策 | Beginner |
| 3 | **Tool/Function Calling** | Agent 调用外部工具（搜索、计算、API）的能力 | Beginner |
| 4 | **Prompt** | 给 LLM 的指令，定义 Agent 的行为边界和输出格式 | Beginner |
| 5 | **ReAct** | 「思考→行动→观察→思考」的循环推理模式 | Beginner |
| 6 | **Memory** | Agent 的「记忆系统」，分短期（上下文）和长期（向量库） | Intermediate |
| 7 | **Planning** | 将复杂目标分解为可执行步骤的能力 | Intermediate |
| 8 | **RAG** | 检索增强生成：从外部知识库检索信息再回答问题 | Intermediate |
| 9 | **Multi-Agent** | 多个 Agent 分工协作完成复杂任务 | Intermediate |
| 10 | **Agentic Workflow** | 将任务设计为 Agent 可执行的标准化流程 | Intermediate |
| 11 | **Chain-of-Thought** | 让 LLM 逐步推理而非直接给答案的提示技巧 | Beginner |
| 12 | **Vector Database** | 存储和检索「语义相似」内容的数据库 | Intermediate |
| 13 | **Embedding** | 将文本转换为数字向量以计算语义相似度 | Intermediate |
| 14 | **Orchestration** | 管理和调度多个 Agent/Tool 协调工作的框架 | Advanced |
| 15 | **Guardrails** | 限制 Agent 行为的「护栏」——防止越权、幻觉、有害输出 | Intermediate |
| 16 | **Evaluation** | 衡量 Agent 输出质量的方法（准确性、效率、安全性） | Advanced |
| 17 | **Fine-tuning** | 在特定数据上进一步训练 LLM 以提升特定任务表现 | Advanced |
| 18 | **Autonomous Agent** | 完全自主决策和执行的 Agent（如 Auto-GPT） | Intermediate |
| 19 | **Human-in-the-Loop** | Agent 在关键节点暂停，等待人类确认的设计模式 | Intermediate |
| 20 | **Agent Protocol** | Agent 间通信和交互的标准协议（如 A2A、MCP） | Advanced |

## 5. Top 10 Confusion Pairs

| # | Concept A | Concept B | Key Difference |
|---|-----------|-----------|----------------|
| 1 | Agent | LLM | LLM 是大脑，Agent 是整个身体（大脑+记忆+工具+行动能力） |
| 2 | RAG | Fine-tuning | RAG 是查资料（外部知识），微调是背课本（内部知识） |
| 3 | Tool Use | Function Calling | Function Calling 是技术实现，Tool Use 是更广义的概念 |
| 4 | ReAct | Chain-of-Thought | CoT 是思考方式，ReAct 是思考+行动+观察的完整循环 |
| 5 | Memory | Context | Context 是短期记忆（对话窗口），Memory 是长期记忆系统 |
| 6 | Multi-Agent | Orchestration | Multi-Agent 是多角色分工，Orchestration 是管理调度的机制 |
| 7 | Agent | Workflow | Workflow 是固定流程，Agent 是动态决策 |
| 8 | Embedding | Vector DB | Embedding 是转换方法，Vector DB 是存储工具 |
| 9 | Autonomous Agent | Human-in-the-Loop | 完全自主 vs 关键节点需人类确认 |
| 10 | Guardrails | Prompt | Prompt 定义行为，Guardrails 限制行为边界 |

## 6. Five Learning Stages

| Stage | After Completing | Deliverable | Days |
|-------|-----------------|-------------|------|
| **1: Foundation** | 理解 Agent 是什么、为什么需要它、核心循环 | 用中文写一篇 Agent 科普文章 | 1-6 |
| **2: Tools & Memory** | 能让 Agent 调用工具、使用记忆 | 手写一个 ReAct Agent 伪代码 | 7-13 |
| **3: Knowledge & Retrieval** | 理解 RAG、向量库、知识注入 | 搭建一个简单的 RAG 问答系统 | 14-20 |
| **4: Multi-Agent & Safety** | 理解多 Agent 协作和安全防护 | 设计一个双 Agent 协作方案 | 21-25 |
| **5: Capstone Project** | 独立完成一个可用的 Agent 项目 | 个人研究助手 Agent | 26-30 |

## 7. The 20-60-20 Split

### Must-Learn-Now (20%)
Agent 定义、LLM 基础、ReAct 循环、Tool/Function Calling、Prompt 工程、Chain-of-Thought、Memory（基础）

### Skip-for-Now (60%)
具体框架的 API 细节、多 Agent 协调的复杂模式、Vector DB 的实现原理、各种 Agent 协议的细节、性能优化技巧

### Learn-Later (20%)
Fine-tuning LLM for Agent、自定义 Orchestration 框架、Agent 安全审计、生产级部署、A2A/MCP 协议实现

## 8. Minimum Viable Knowledge

要做出一个可用的 Agent，你只需要这 8 项：
1. 什么是 Agent
2. LLM 基本用法（API 调用）
3. Prompt 编写（System Prompt + User Prompt）
4. Function Calling（至少一个工具）
5. ReAct 循环逻辑
6. 简单的 Memory（对话历史存储）
7. 基本的错误处理
8. 一个可运行的 demo

## 9. What NOT to Learn Yet

- ❌ LangChain/LlamaIndex 的完整 API（先理解原理，框架后补）
- ❌ 各种 Agent 框架的对比（Auto-GPT vs CrewAI vs LangGraph）
- ❌ Vector DB 的底层索引算法（HNSW 原理）
- ❌ MCP/A2A 协议规范
- ❌ Agent 生产部署（Docker、K8s、监控）
- ❌ 自定义 Fine-tuning
- ❌ 多 Agent 博弈论
