# Learn Anything 学习协议

本协议定义平台无关的学习闭环。任何平台适配版本都必须保留这些行为，即使没有文件读写、联网或工作流能力。

## 适用场景

- 用户要系统学习一个领域，而不是只要一次性问答。
- 用户希望生成学习计划、知识地图、练习、测验、复盘或项目。
- 用户提供 PDF、PPT、Markdown、TXT、Word、网页导出、截图或课程笔记作为学习范围。
- 用户需要跨多次会话追踪进度和薄弱点。

## 学习变量

| 变量 | 含义 |
| --- | --- |
| `domain` | 学习领域 |
| `domain_slug` | 文件或状态中使用的英文短名 |
| `user_background` | 零基础、入门、中级、高级 |
| `daily_time` | 每天可投入时间 |
| `duration` | 总学习天数，默认 30 天 |
| `learning_goal` | 考试、工作、项目、写作、研究等 |
| `final_artifact` | 最终要完成的作品或项目 |
| `interface_language` | 与用户沟通的语言 |
| `learning_language` | 学习内容输出语言 |
| `material_mode` | 是否由用户资料定义学习范围 |
| `web_access` | 是否可联网核查 |
| `file_read_access` | 是否可读取用户资料 |
| `file_write_access` | 是否可写入学习仓库 |
| `workflow_access` | 是否可使用平台工作流 |

## 固定学习闭环

每次学习都遵循：

1. **intake**：确认领域、背景、时间、目标、最终作品、资料、语言、平台能力。
2. **map**：生成知识地图，说明核心概念、依赖关系、混淆点、学习阶段和最小可用知识。
3. **plan**：生成阶段计划，每天包含概念、练习、输出任务和验收标准。
4. **learn**：用“解释 -> 示例 -> 练习 -> 检查 -> 复盘”完成当天学习。
5. **practice**：每次至少包含 5 个问题，覆盖记忆、应用和综合。
6. **deliver**：每次至少产生一个可检查的小成果。
7. **assess**：每 7 天进行阶段测试，先出题，等用户作答后再评分。
8. **diagnose**：错误先归因，再给答案和补救练习。
9. **review**：更新进度、薄弱点、下一步计划和来源记录。
10. **project**：最后阶段用项目验证迁移能力。

## 错误类型

| 标签 | 中文含义 | 处理方式 |
| --- | --- | --- |
| `[concept-gap]` | 不懂概念 | 回到定义、类比和最小例子 |
| `[application-failure]` | 不会应用 | 增加情境题和拆步骤练习 |
| `[expression-unclear]` | 表达不清 | 要求用户复述并改写 |
| `[knowledge-confusion]` | 知识混淆 | 做对比表和辨析题 |

## 不可省略规则

- 不输出只有讲解、没有练习和任务的学习课。
- 不在用户作答前泄露测验答案。
- 不把阶段测试变成普通问答。
- 不把学习计划写成泛泛建议，必须包含可完成的任务。
- 不让平台限制破坏学习闭环；缺少能力时必须降级。

## 平台降级

| 缺失能力 | 降级方式 |
| --- | --- |
| 无文件写入 | 输出带路径标题的 Markdown 代码块，让用户保存 |
| 无文件读取 | 要求用户粘贴文本、提供 OCR、转换为 Markdown/TXT，或只生成资料处理清单 |
| 无联网 | 标记为未验证草稿，生成待核查清单 |
| 无工作流 | 用单轮或多轮提示词模拟阶段流程 |
| 无长期记忆 | 每次输出并要求用户保留 `learning_state` 摘要 |
