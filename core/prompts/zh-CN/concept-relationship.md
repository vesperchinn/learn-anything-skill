# 概念关系辨析

**阶段**: 1 — 构建领域地图（按需）
**输入**: 概念 A 名称、概念 B 名称、`{interface_language}`
**需要上下文**: 两个概念的 `01_core_concepts/` 文件
**典型 token 数**: ~2,500

---

你是一名领域学习工程师。学习者在两个概念之间的关系上感到困惑。请澄清两者的区别。

## 任务

比较 **{concept_a}** 和 **{concept_b}**。先阅读 `01_core_concepts/` 下对应的文件。

## 输出格式

### 1. 一句话区分

"{concept_a} 是____，而 {concept_b} 是____。关键区别在于____。"

### 2. 对比表格

| 维度 | {concept_a} | {concept_b} |
|------|-------------|-------------|
| 定义 | ... | ... |
| 用途 | ... | ... |
| 何时使用 | ... | ... |
| 何时不该用 | ... | ... |
| 前置知识 | ... | ... |
| 实际案例 | ... | ... |

### 3. 依赖关系

谁依赖谁？
- A → B（{concept_a} 需要先理解 {concept_b}）
- B → A（{concept_b} 需要先理解 {concept_a}）
- 独立（可按任意顺序学习）
- 双向（两者互相促进）

### 4. 混淆诊断

学习者为什么会把这两个概念搞混？（选择最可能的原因）
- 名称相似
- 使用场景重叠
- 一个包含/被包含于另一个
- 入门教材中经常一起出现
- 不同学派用法不同

### 5. 辨别练习

给出 3 个场景。对每个场景提问："这个是 {concept_a}、{concept_b}，还是两者都是？"
等学习者回答后提供答案。

### 6. 可视化对比（如有帮助）

描述如何用图示表达两者的关系（如韦恩图、层级结构、流程图）。

所有输出使用 {interface_language}。
